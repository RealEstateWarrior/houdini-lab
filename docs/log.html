001で「回数を増やすと立方体が球に近づく」と気づいたので、数値で確かめた。 重要なのは4通りすべてを同じカメラで撮っていること。各変種を自動でフレームに収めると 大きさの違いが消えて比較にならない。

わかったこと

  • 数は1回ごとに正確に4倍。四角形1枚が4枚に割れるため。3回で64倍、6回で4096倍なので、回数を安易に増やすと破綻する。
  • 数は常に「プリミティブ数 + 2」。オイラーの多面体定理から導ける。閉じた四角形では各辺を2面が共有するので E = 2F、これを V − E + F = 2 に代入すると V = F + 2。実測7通りすべて一致した。
  • 1回目だけ一辺が縮まない。+X端を保持している点を調べたら (0.5, 0, 0) の1点だけで、これは元の +X 面の中心そのものだった。 は各面の中心に新しい点を作るので、1回目はその新点が元の面上に乗る。2回目でその点も内側に引かれ 0.87847 に縮む。
  • 縮みの原因は分割ではなく平滑化だと確定した。OpenSubdiv Bilinear（平滑化せず分割するだけ）で3回分割しても一辺は 1.00000 のまま。面数は同じ384なので、分割量は同じで平滑化の有無だけが違う。
  • 一辺の縮み方は等比的に収束する。差は 0.02929 → 0.00726 → 0.00181 → 0.00045 で毎回およそ1/4。外挿した極限値は約 0.83951。
  • この外挿は当たっていた（実験030）。8回まで回すと一辺は 0.839516 で、0.83951 との差は 0.000006。差が毎回およそ1/4に減るという読みも、0.243 / 0.248 / 0.249 / 0.249 / 0.245 / 0.231 と保たれた。
  • -Compatible Catmull-Clark は回数1〜5のどれでも一辺が 0.83951 で一定だった。上で外挿した極限値と一致する。つまりこのモードは繰り返して近づけるのではなく、極限曲面上の位置を直接求めている。
  • だけプリミティブ数が768になる（他は384）。三角形メッシュ向けの方式なので四角形が三角形に割られる。四角形を保ちたい場面では選べない。

mountain と subdivide は、順序を変えると何が変わるか

/obj/order_compare  ·  ノード 14 / 接続 13

使ったノードsubdividemountain

シーンファイル003_order.hipnc

001で立てた「細かい凹凸を出すには先に分割数を上げる必要がある」という見込みを検証した。 height = 0.35 は全変種で固定し、D と E だけ elementsize（の特徴サイズ）を 0.8 から 0.25 に下げている。

この実験は測り方を一度間違えている。最初に表面積を指標に選んだが違いが正しく出ず、 途中で別の指標に切り替えた。その経緯も残した。

基準形（ノイズなし）からの点ごとのずれ

変種ポイント平均のずれ最大のずれ
A: mountain → subdivide(2)980.020690.03671
B: subdivide(2) → mountain980.024790.08062
C: subdivide(3) → mountain3860.025040.08009

同じ分割回数なら点の順序も同じなので、ノイズなしの基準形と1点ずつ引き算できる。 これが「ノイズがどれだけ形を動かしたか」を直接表す。

わかったこと

  • 順序を入れ替えても点数・面数は同じ（どちらも98点 / 96面）。データの重さは変わらず、形だけが変わる。
  • 最大のずれは A が 0.03671、B が 0.08062 でBが約2.2倍大きい。分割したあとにノイズをかけた方が凹凸が残る。001の見込みは正しかった。
  • 理由も測れた。box に をかけた直後は8点すべてが平均 0.03607 動いている。ところが を通すとずれは平均 0.02069・最大 0.03671 まで下がる。 の平滑化は周囲の点を平均するので、せっかく作った凹凸をなめしてしまう。
  • C は B とほぼ同じずれだった（平均 0.02504 対 0.02479）。点を4倍に増やしても凹凸の大きさは変わらない。点数は振幅を決めていない。
  • 振幅を決めていたのは elementsize だった。C と D は同じ386点だが、0.8 から 0.25 に下げると平均のずれが 0.02504 → 0.03236 に増え、画も明確に岩になった。
  • E は D と同じノイズ設定で点数だけ4倍。平均のずれは 0.03236 → 0.03239 でほぼ不変だが、画は同じ起伏をより滑らかな面で表現できている。つまり点数は解像度を、elementsize は振幅を決めている。
  • ただし最大のずれだけは点数とともに少し増える（0.11985 → 0.13173）。点が増えるとノイズのより極端な場所まで拾えるためで、振幅が増えたわけではない。
  • 実用的な結論: 細かいディテールが欲しいなら、分割数を上げるだけでは足りない。elementsize も一緒に小さくし、mountain は分割のあとに置く。この3つが揃って初めて狙った凹凸になる。

測り方の反省。表面積のように「全体をひとつの数にまとめた量」は、大きさの変化と形の変化が混ざる。 実際 mountain を足すと表面積は減った（2.43164 → 2.24947）。ノイズが内側にも押して全体が縮み、 面積は大きさの2乗に比例するのでその影響が勝っていた。 比較実験では、まず基準形を作り、それと1対1で対応づけられる量を選ぶべきだった。

mountain のノイズパラメータは、それぞれ何に効くのか

/obj/mountain_params  ·  ノード 15

使ったノードspheremountain

シーンファイル004_mountain_params.hipnc

003で「点数は解像度、elementsize は振幅」と分かった。では残りのは何を変えているのか。

最初に分かったのは名前の問題だった。パラメータ名は roughness や octaves ではなく rough / oct / lac。 一般的な名前で書くとパラメータが見つからずエラーになる。

そして003で使った「基準形からのずれ」だけでは、これらをほとんど区別できなかった。 平均のずれはどれも 0.032〜0.034 に収まる。振幅ではなく形の性質を変えるパラメータだったため、 性質を測る指標を新しく用意した。隣り合う点どうしで、ずれの向きと量がどれだけ食い違うかを測る。 なだらかな起伏なら隣も同じように動くので小さく、細かい凹凸なら大きくなる。

rough — 振幅は変えず、細かさだけを変える

固定条件はすべて共通: 4回（1538点）、height 0.35、elementsize 0.25。 平均のずれはほぼ変わらないのに、なだらかな丘から棘だらけの形まで変わる。

予測の検証 — oct が 3 以上で効かないのは点数のせいか

subdivide点数oct = 1oct = 3oct = 88 と 3 の差
3回3860.026920.028680.02856−0.00012

「oct が効かないのは点数が足りないからだ」が正しいなら、点数を増やせば oct=8 が oct=3 を上回るはず。 実際にそうなった。なお食い違いの絶対値は点数が増えると小さくなる（隣同士が近づくため）ので、 各行の中だけで比較できる表で、行をまたいで比べてはいけない。

わかったこと

  • 既定値は rough 0.5、oct 8、lac 1.841、fractal Hybrid Terrain、basis Simplex。使う前に実際のパラメータ名を確認する必要がある（roughness は存在しない）。
  • rough が細かさに最も強く効く。0.0 → 1.0 で食い違いが 0.01350 → 0.03233（約2.4倍）になる一方、平均のずれは 0.03377 → 0.03235 でほぼ変わらない。同じ振幅のまま、形の性質だけを変えるパラメータ。
  • rough = 0.0 の数値は fractal = None と完全に一致した（平均 0.03377、最大 0.14799、食い違い 0.01350）。rough = 0 では追加の層が何も足さないので、層を重ねない単一に退化している。別経路で同じ結果に着いたので、この解釈は確かだと言える。
  • oct は 1 → 3 では効くが、3 → 8 ではほぼ変わらない（差 0.00001）。点数が足りず細かい層を表現できていないため。oct を上げるなら点数も上げないと無駄。003の「点数は解像度を決める」が別角度から確認できた。
  • lac（層ごとの周波数の開き）も細かさに効く（1.5 → 4.0 で 0.01259 → 0.02218）。ただし lac = 1.5 では平均のずれも 0.02625 に下がるので、rough のようにきれいに性質だけを変えるわけではない。
  • fractal の4種類は今回の条件では差が小さかった（食い違い 0.01350〜0.01786）。地形向けの方式が揃っているので、平面の地形ならもっと差が出る可能性がある。
  • basis（ノイズの基礎となる種類）は14種類あった。Worley Cellular のようなセル状のものも含まれ、見た目が大きく変わるはず。次の実験にする。

指標について。003で作った「基準形からのずれ」は振幅を測る道具で、今回のパラメータには盲目だった。 測りたいものが変われば、指標も作り直す必要がある。 今回足した「隣との食い違い」は、同じ点数の中でだけ有効な指標であることにも注意。

わかったこと

  • 同じ height 0.35 でも、平均のずれは Periodic Perlin Flow の 0.01551 から Sinusoid の 0.14454 まで約9.3倍開く。basis を変えたら height も再調整が必要。

  • Perlin 系（perlin / pperlin / flow / pflow）は外向きの点が 40〜59% で、外と内にほぼ均等に動く。平均のずれも 0.0155〜0.0264 と控えめ。自然な揺らぎを足したいときの素直な選択肢。

  • セル系で外向き率が真っ二つに分かれた。Manhattan F1 が 91.1%、Chebyshev F1 が 94.4% でほぼ全点が外に出る。一方 Worley F1 は 5.4%、Alligator は 2.3%、Chebyshev F2-F1 は 1.4% でほぼ全点が内に削られる。
  • 画で理由が見えた。Worley F1 は細胞の中心から遠いところが深く削られ、侵食岩のようになる。Manhattan F1 は距離の測り方が軸に沿っているため、軸に平行な面を持つ角ばった塊が外に突き出す。同じ「F1」でも距離の定義が違うと、削る向きと形がまったく変わる。
  • F1 と F2-F1 の違いも外向き率に出る。Manhattan は F1 が 91.1%（外向き）なのに F2-F1 は 2.5%（内向き）。Chebyshev も同じ傾向。F2-F1 は細胞の境界線を強調する計算なので、境界以外が下がる＝内向きになる。
  • 実用指針: 突起を作りたいなら Manhattan F1 か Chebyshev F1、窪みや侵食なら Worley F1 か Alligator、自然な揺らぎなら Perlin 系、大きなうねりなら Sinusoid。

最大のずれはセル系でほぼ頭打ちになっている（0.164〜0.175）。 height 0.35 に対して 0.5 倍弱で止まっており、何らかの上限が効いている可能性がある。 これは実験006で確かめる。

height は純粋な倍率か。gain と bias は何に効くか

/obj/height_shape  ·  height を16倍の範囲で振る

使ったノードspheremountain

シーンファイル006_height_shape.hipnc

005で「セル系の最大のずれが 0.175 付近で止まっているので、何らかの上限が効いている 可能性がある」と書いた。それを確かめた。

結論から言うと、005の見立ては誤りだった。上限は存在しない。 そして高い height で比率が崩れたのは Houdini の制限ではなく、 私が使っている指標が壊れていたためだった。

わかったこと

  • height は純粋な倍率だった。「最大 / height」は 0.0875 から 0.7 まで8倍の範囲で小数点以下4桁まで一定（simplex 0.3759、worleyFA 0.4951）。height を2倍にすればずれもきっちり2倍になる。
  • 005で疑った上限は存在しなかった。 セル系の最大が揃って見えたのは、セル系のピーク値の分布が互いに似ているため。005のセル系7種類の「最大 / height」を計算すると 0.47〜0.50 に収まる一方、simplex は 0.376 で明確に違う。上限ではなく種類ごとの固有の比率だった。
  • height = 1.4 で比率が両方とも 0.307 に落ちたのは、私の指標が壊れているため。基準形の半径は約 0.42（の一辺 0.84192 の半分）で、測れた最大のずれ 0.4312 / 0.4298 はこれとほぼ一致する。中心を貫通するほど押し込まれると「中心からの距離の差」では値が頭打ちになる。
  • つまりこの指標はずれが対象の半径より十分小さいときにしか使えない。005の観察を「上限がある」と解釈しかけたのは、この限界を意識していなかったため。指標を作ったら、それが壊れる条件も押さえておく必要がある。
  • clipmin / clipmax の既定は 0.0 / 1.0、dogain / dobias は既定で無効。005までの測定に余計な処理は入っていなかったと確認できた。
  • gain は振幅の倍率。0.25 / 0.5 / 0.75 で平均のずれが 0.01494 / 0.03237 / 0.05519 と増える一方、外向きの点の割合は 35.8% のまま完全に動かない。強さだけを変える。
  • bias は外向きと内向きの比率を直接変える。 0.25 で外向き 0.9%、0.5 で 35.8%、0.75 で 98.7%。005では basis を選ぶことでしか得られなかった「突起か窪みか」の制御が、1つので連続的にできる。
  • ただし bias を 0.5 から動かすと平均のずれも増える（0.03237 → 0.09756 / 0.07644）。分布が片側に寄るとゼロから離れた点が増えるため。形の偏りだけを変えるわけではない。

のパラメータ地図（実験003〜006のまとめ）
振幅を決めるのは height（純粋な倍率）と gain（倍率）。 細かさを決めるのは rough（最も強い）、lac、oct（点数が足りている範囲で）。 外向きか内向きかを決めるのは bias（連続的）と basis（種類で決まる）。 特徴の大きさは elementsize。そして何を表現できるかの上限は点数が決める。

凸凹の付け方3通り — 輪郭を見れば、どれが本当に形を変えたか分かる

シーンファイル041_disp.hipnc

面を凸凹させる方法は3つある。 を動かす（点そのものを動かす）、 displacement（レンダのときだけ面を動かす）、 bump（面は動かさず光の当たり方だけ凸凹に見せる）。

見た目はどれも似る。決定的な違いは輪郭（シルエット）に出るはずである。 本当に面が動いていればフチがぎざぎざになり、光のごまかしならフチは滑らかなままになる。 そこで輪郭の長さを測った。書き出した画の透明度から、 地形と背景の境目になっている画素を数える。

何もしない0.0000003,0641.000倍2.29454.32秒

displacement0.0000003,1261.020倍3.51736.32秒
bump0.0000003,0620.999倍4.05248.32秒

bump は画の細かさが一番大きい（1.77倍）のに、輪郭は変わらない。 displacement は点を1ミリも動かさないのに、輪郭を変える。

わかったこと

  • bump は輪郭をまったく変えなかった。3,062 対 3,064 で 0.999倍。それでいて画の細かさは一番大きい。凸凹して見えるのに、形は1ミリも変わっていない。
  • displacement は点を動かさないのに輪郭を変えた。点の移動量は 0.000000 なのに輪郭は 1.020倍。レンダのときだけ面が動くので、データを見ても分からない。
  • ジオメトリを動かした場合だけ、データが変わる。点が最大 2.22 動き、高さの幅も 28.519 → 29.562 に広がった。あとの工程（散布や当たり判定）に効くのはこれだけ。
  • 使い分けの目安。フチに出したい凸凹はジオメトリか displacement、面の中だけでよい細かさは bump。遠景の岩肌なら bump で足り、シルエットに出したい割れ目なら displacement が要る。
  • bump が一番遅かった。8.32秒で、何もしない場合の 1.9倍。displacement（6.32秒）より遅い。「面を動かさないから軽い」とは限らない。理由は測っていないので断定しない。
  • 最初、bump がまったく効かなかった。有効化のスイッチだけ入れてテクスチャのパスを指定していなかったため、輪郭も細かさも「何もしない」と完全に同じ数字（3056 と 2.2916）になった。完全に同じ数字が出たら、効いていないことを疑う。
  • 輪郭の測り方。透明度で地形と背景を分け、隣り合う画素で「地形かどうか」が食い違う場所の数を数えた。実験038で「明るさで分けると白飛びを取りこぼす」と学んだので、透明度で分けている。
  • 差は2%前後と小さい。目で見比べても分からない大きさだが、数えれば順番がはっきり出る。bump だけが 1.000倍から動かず、他の2つは 1.018 / 1.020 と揃って上がる。

実験029で、粒に当てる popwind は 二次の抵抗（dv/dt = a(W−v)²）だと突き止めた。毛の場合はどうか。

まず条件をそろえるのに2回つまずいた。1回目は、カメラの高さの比を物を回すときと変えてしまい、比べられなかった。2回目は、文字を原点のまわりに置くずらし量を当て推量で入れていて、回すと画の中で位置がずれた。外接箱の真ん中を測ってずらし直すと、ようやく比べられる形になった。

そろえて撮ると、形はぴったり同じだった。シルエット（画面に占める割合）は、4コマとも 7.61% / 7.61%、9.28% / 9.29%、9.83% / 9.83%、9.04% / 9.05%。
