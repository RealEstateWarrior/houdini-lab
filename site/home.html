この場所の決めごと

  • Houdiniの挙動は実測を正とする。 ネットの情報は出典を確認し、動かせるものは動かして確かめる。実際に「Apprenticeではhythonが使えない」「mountainのパラメータは roughness という名前」はどちらも誤りだった。
  • 測り方も記録する。 実験003では最初に選んだ指標（表面積）が不適切で途中で切り替えた。004でも指標を1つ足している。失敗した測り方も残す。
  • 仮説は否定できる条件で試す。 「縮む原因は平滑化」の検証には、平滑化しない Bilinear を使った。「octが効かないのは点数のせい」は、点数を増やして予測どおりになるかを確かめた。
  • Notebookのソースは増やしすぎない。 上限300件。実験1件ごとに1ソース足すと無駄に消費するので、テーマ単位で1ソースにまとめ、実験が増えたらそのソースを差し替える。
  • 用語は1か所で管理する。 glossary.json を単一の情報源にして、この用語集タブ・実験ログのポップアップ・Notebook用PDFの3つを生成している。説明が食い違わない。
  • 話がつながらない実験は分ける。 現在の001〜004はひとつながりの流れなので同じログにまとめている。エフェクトに入ったら別のログに分ける。

Experiments

実験

サムネイルを押すと、その実験の詳細に移動する（ここで初めて読み込みが入る）。 001から004はひとつながりの流れなので、同じログにまとめている。

001 で最小構成を組んだときに「分割を重ねると立方体が球になる」と気づいた。 → 002 でそれを数えて、縮む原因が平滑化だと確定させた。 → 003 では「ならノイズは分割の前か後か」を比べ、点数は解像度を決めるだけで 凹凸の大きさは elementsize が決めていると分かった。 → 004 で残りのノイズパラメータを切り分け、rough が形の性質を、 oct は点数が足りている範囲でしか効かないことを確かめた。 → 005 ではノイズの種類そのものを14通り並べ、種類によって 外向きに押すか内向きに削るかが決まると分かった。 → 006 でそこで疑った「上限」を検証したところ、上限は存在せず、 むしろ自分の指標が壊れていたと判明した。あわせて bias が突起と窪みを 連続的に制御できると分かり、mountain のパラメータ地図がほぼ埋まった。 → 007 では舞台を平面に移し、球体では使えなかった指標を作り直した。 勾配が増えなくなる点が「その形に足りている解像度」を教えてくれると分かった。 → 008 でパラメータの調査を離れ、地面に物を生やす定番パターンに進んだ。 複製の向きが N のどの軸に対応するかを200個すべて測り、Z軸だと確定させた。

 実験 002

subdivide の回数で、形と数はどう変わるか

面数は正確に4倍、点数は常に面数+2。縮む原因は分割ではなく平滑化

 実験 003

mountain と subdivide は、順序を変えると何が変わるか

点数は解像度を決め、凹凸の大きさは elementsize が決める

 実験 004

mountain のノイズパラメータは、それぞれ何に効くのか

rough が形の性質を決める。oct は点数が足りないと効かない

 実験 005

basis 14通りで、形はどこまで変わるか

振幅も性質も変わる。外向きに押すか内向きに削るかが種類で決まる

 実験 006

height は純粋な倍率か。gain と bias は何に効くか

005の「上限がある」は誤りだった。bias で突起と窪みを連続的に制御できる

Terminology

用語集

Houdiniは略語と英語の専門用語が多く、意味が分からないまま読み進めると手が止まる。 前提知識なしで読めるようにまとめた。カタカナ読みを併記しているのは、 そもそも何と読むのか分からない語が多いため。

単独ページとしても用語辞典にある（見出しへのリンクを共有したいとき用）。

ネットワークと文脈

Houdiniは「どの階層で作業しているか」で使えるノードが変わる。その階層の名前が SOP や DOP といった略語になっている。

ノード / Nodeノード
ひとつの処理を表す箱。入力を受け取り、加工して出力する。Houdiniではこの箱をつないで結果を作るため、作業そのものが「箱をつなぐこと」になる。
ネットワーク / Networkネットワーク
ノードをつないだ全体のこと。上から下へ流れる図として表示され、これを編集する画面をネットワークエディタと呼ぶ。
SOPソップ · Surface Operator
ジオメトリ（形）を扱うノードの階層。box、mountain、subdivide など、モデリングで使うノードはほぼSOP。Houdiniで最初に慣れるべき場所。関連: ジオメトリ
POPポップ · Particle Operator
パーティクル（粒子）を扱うノードの系統。火花、雨、群衆のように「たくさんの小さなものが動く」表現に使う。シミュレーション用のネットワークの中で組む。関連: DOP, シミュレーション
DOPドップ · Dynamics Operator
シミュレーション（物理計算）を扱う階層。破壊、布、煙、液体などはここで計算する。時間をフレームごとに進めながら結果を積み上げていくのが特徴。関連: ソルバ, シミュレーション
VOPボップ · VEX Operator
VEXの処理をノードをつないで組み立てる階層。コードを書く代わりに図で書くVEX、という位置づけ。関連: VEX
ROPロップ · Render Operator
出力を担当するノードの階層。画像のレンダリング、ファイル書き出しなど「最終的に何かを外に出す」処理はここ。関連: Karma, OpenGL ROP
OBJオブジェ · Object
シーンに置く「物体」の階層。カメラ、ライト、ジオメトリの入れ物（geoノード）などが並ぶ。SOPはこのgeoノードの中に入っている。
LOPロップ · Lighting Operator
USDベースでシーンを組む階層。Solarisとも呼ばれる。ライティングやレンダリングの設定を扱う新しい仕組み。

ジオメトリの構成要素

Houdiniは形を「ポイント」「バーテックス」「プリミティブ」に分けて扱う。ここの区別が分かるかどうかで理解度が大きく変わる。

ジオメトリ / Geometryジオメトリ
形のデータそのもの。ポイントやプリミティブの集まりを指す。ノードからノードへ流れていくのはこのジオメトリ。
ポイント / Pointポイント
空間上の位置を持つ点。位置は必ず P という属性として持っている。形の頂点にあたるが、Houdiniでは「位置を持つだけの存在」として独立している。関連: バーテックス, P
バーテックス / Vertexバーテックス
プリミティブ（面）の角。どのポイントを使うかを指し示すだけの存在。2つの面が同じ角を共有している場合、ポイントは1つだがバーテックスは2つある。UVや面ごとの法線はこちらに乗る。初心者が最も混乱する区別。関連: ポイント, プリミティブ
プリミティブ / Primitiveプリミティブ
面や線、ボリュームなど「形の単位」。ポリゴン1枚がプリミティブ1つ。立方体なら6面あるのでプリミティブは6つ。prim と略される。関連: ポリゴン, バーテックス
ポリゴン / Polygonポリゴン
3つ以上のバーテックスで囲まれた面。プリミティブの一種で、モデリングで最もよく使う種類。
アトリビュート / Attributeアトリビュート
ジオメトリに付けられる名前付きのデータ。位置、色、速度、大きさなど何でも持たせられる。Houdiniの柔軟さの正体はこれで、「必要な情報を自分で作って後段のノードに渡す」のが基本的な考え方。属性とも書く。関連: P, N, Cd, ディテールアトリビュート
Pピー
ポイントの位置を表すアトリビュート。x, y, z の3つの数値。すべてのポイントが必ず持っている。
Nエヌ · Normal
法線。面や点が向いている方向を表すベクトル。ライティングの計算や、押し出す方向の基準に使われる。関連: 法線
Cdシーディー · Color diffuse
色を表すアトリビュート。RGBの3つの数値。color SOP を通すとこれが追加される。
pscaleピースケール
ポイントごとの大きさ。copy to points で形を複製するときに、このアトリビュートで1つずつサイズを変えられる。関連: copy to points
@ptnumアットピーティーナム · point number
ポイントの通し番号（0から始まる）。VEXの中で「何番目の点か」を知るために使う。@ が付く書き方はVEXでのアトリビュート参照。関連: VEX
ディテールアトリビュート / Detail attributeディテールアトリビュート
ジオメトリ全体に1つだけ持たせる値。ポイントごとではなく「この形全体の設定」を渡したいときに使う。グローバルアトリビュートとも呼ばれる。関連: アトリビュート
トポロジ / Topologyトポロジ
ポイントがどうつながって面を作っているか、というつながり方の構造。位置を動かしてもトポロジは変わらないが、分割したり穴を開けると変わる。
法線 / Normalほうせん
面が向いている向きを示す矢印。裏表の判定やライティングに使われる。これが裏返っていると面が真っ黒に見えたり消えたりする。関連: N
UVユーブイ
テクスチャ（画像）を形に貼るための座標。3Dの形を平面に展開した位置を、バーテックスごとに持たせる。関連: バーテックス
バウンディングボックス / Bounding boxバウンディングボックス
ジオメトリ全体がちょうど収まる直方体。大きさや位置の目安として使われ、これを基準に色を付けたり配置したりできる。bbox と略される。
グループ / Groupグループ
ポイントやプリミティブに名前を付けた選択範囲。「この部分だけに処理をかけたい」というときに作る。
ボリューム / Volumeボリューム
空間を格子状に区切って、各マスに値を持たせたデータ。煙や炎のように「面では表せない、中身のあるもの」を扱うのに使う。VDBはその代表的な形式。関連: Pyro

よく使う処理

SOPで頻繁に登場する処理。名前が動作をそのまま表しているものが多い。

subdivideサブディバイド
面を細かく分割するノード。分割と同時に形を滑らかにするため、立方体にかけると回数を増やすほど球に近づく。この滑らかにする方式が Catmull-Clark。関連: Catmull-Clark
Catmull-Clarkカトマル・クラーク
面を分割しながら滑らかな曲面に近づけていく計算方式。角が丸まるのが特徴で、「分割したのに形が変わった」と感じる原因はこれ。関連: subdivide
mountainマウンテン
ポイントを法線方向にノイズで押し出して、地形のような凹凸を作るノード。既存のポイントを動かすだけでポイントは増えないため、細かい凹凸を出したいなら先に分割数を上げておく必要がある。関連: ノイズ, subdivide
ノイズ / Noiseノイズ
でたらめに見えて滑らかにつながっている数値のパターン。自然物のばらつきを作るのに使われ、地形、煙、揺れなどほぼすべての「自然に見せたいもの」の元になる。
scatterスキャッター
面の上にポイントをばらまくノード。ばらまいた点にあとから草や岩を複製する、という流れがプロシージャルの定番。関連: copy to points
copy to pointsコピー・トゥ・ポインツ
ポイントの位置1つずつに、別のジオメトリを複製して配置するノード。「100個の岩を並べる」ような作業を1ノードで済ませられる、プロシージャルの中核。関連: scatter, pscale
mergeマージ
複数のジオメトリを1つにまとめるノード。別々に作った形を合流させる合流点として使う。
for-each / フォーイーチフォーイーチ
同じ処理をパーツごとに繰り返す仕組み。Block Begin と Block End という2つのノードで範囲を挟んで作る。「破片1つずつに別々の動きを付ける」など、まとめて処理できないときに使う。関連: イテレーション
イテレーション / Iterationイテレーション
繰り返し処理の1回分。10個のパーツを順に処理するなら、イテレーションは10回ある。「今が何回目か」を数値として取り出して、回ごとに違う結果にすることができる。関連: for-each
wrangleラングル
VEXのコードを直接書き込めるノード。attribute wrangle が代表。ノードを並べるより、数行書いた方が早くて分かりやすい場面で使う。関連: VEX
VEXベックス
Houdini専用のプログラミング言語。ポイント1つ1つに対して同じ計算を一斉に走らせるため非常に速い。`@P.y += 1;` のように短く書ける。関連: wrangle, VOP
polyextrudeポリエクストルード
面を押し出して厚みや突起を作るノード。建物の階や、壁からの出っ張りなどを作るのに使う。
booleanブーリアン
2つの形を足す・引く・重なりを取る、という演算をするノード。四角から円柱を引いて穴を開ける、といった使い方。
voronoi fractureボロノイ・フラクチャー
ジオメトリを細胞のような塊に分割するノード。破壊エフェクトで、壊れる前にあらかじめ破片を作っておくために使う。関連: RBD

シミュレーション

時間を進めながら計算するもの。1フレーム目の結果を使って2フレーム目を計算するため、途中から飛ばして見ることができない。

シミュレーション / Simulationシミュレーション
物理法則にもとづいて動きを計算させること。手で動きを付けるのではなく、条件を与えて結果を計算させる。略してsimとも書く。
ソルバ / Solverソルバ
シミュレーションの計算を担当するノード。剛体用、布用、煙用など対象ごとに専用のソルバがある。
RBDアールビーディー · Rigid Body Dynamics
変形しない硬い物体の物理計算。積み木が崩れる、壁が砕けて飛び散る、といった動きを担当する。関連: voronoi fracture
Vellumベラム
布、ゴム、髪のような柔らかいものを扱うソルバ。比較的軽く扱いやすいため、柔らかいものを試すならまずここから。
Pyroパイロ
煙と炎を扱うソルバ。ボリュームとして計算するため、面のモデリングとは考え方がかなり違う。関連: ボリューム
FLIPフリップ · Fluid-Implicit-Particle
液体を扱うソルバ。液体をパーティクルとして計算し、最後に表面を張って水面にする。
サブステップ / Substepsサブステップ
1フレームの中を何回に分けて計算するかの設定。動きが速すぎて突き抜けてしまうときに増やす。増やすと正確になるが時間もかかる。
キャッシュ / Cacheキャッシュ
計算結果をファイルに保存しておくこと。シミュレーションは重いため、一度計算したら保存して使い回すのが前提。file cache ノードで行う。
フレーム / Frameフレーム
アニメーションの1コマ。24フレームで1秒が一般的。シミュレーションはフレームを順に進めながら計算する。

表示とレンダリング

画面で確認するための表示と、画像として書き出すレンダリングは別物。

レンダリング / Renderレンダリング
3Dのシーンから画像を計算して作ること。光の反射や影を計算するため時間がかかる。
Karmaカルマ
Houdiniに付属する現行のレンダラー。品質が高いが計算に時間がかかる。
Mantraマントラ
Houdiniの旧世代レンダラー。現在はKarmaに置き換わりつつある。
OpenGL ROPオープンジーエル・ロップ
ビューポートの表示をそのまま画像に書き出すノード。光の計算をしないため一瞬で終わる。「何ができたか確認する」用途に向く。関連: ROP, ビューポート
ビューポート / Viewportビューポート
3Dの形を表示している画面。ここで見えているものは簡易表示で、レンダリング結果とは異なる。
Smooth Wire Shadedスムース・ワイヤー・シェーデッド
表示モードの一種。面に色を付けたうえで、面の境界線（ワイヤーフレーム）も重ねて描く。分割数やトポロジを確認したいときに有効。関連: トポロジ
ワイヤーフレーム / Wireframeワイヤーフレーム
面を塗らず、辺だけを線で表示すること。形の内部構造や分割数を見るのに使う。
フリップブック / Flipbookフリップブック
ビューポートの表示を連続して画像に書き出し、動きを確認すること。レンダリングせずにアニメーションを見たいときに使う。
距離減衰 / Falloffきょりげんすい
光が遠くなるほど弱くなる性質。ポイントライトは距離の2乗で暗くなるため、遠くに置くと強度を大きく上げないと真っ暗になる。
distant lightディスタント・ライト
太陽のように平行な光を当てるライト。距離による減衰がないため、どこに置いても明るさが変わらない。関連: 距離減衰
dome light / envlightドーム・ライト
シーン全体を包む球から光を当てるライト。全方向から柔らかく照らせるので、形を確認したいときに扱いやすい。

Houdini そのものに関する語

ファイル形式やツール名など、操作の周辺で出てくる語。

パラメータ / Parameterパラメータ
ノードの設定値。高さ、回数、サイズなど。parm と略される。Houdiniではこの値に数式を入れて他のノードと連動させられる。
クック / Cookクック
ノードが実際に計算を行うこと。パラメータや入力が変わると、そのノードと下流が再クックされる。重いノードを触ると待たされるのはこれが走っているため。
表示フラグ / Display flagディスプレイ・フラグ
どのノードの結果を画面に表示するかの指定。ノードの端に付く点で示される。「途中のノードを見る」ができるのはこの仕組みのおかげ。
バイパス / Bypassバイパス
ノードを一時的に無効にして、入力をそのまま下流に流すこと。そのノードの効果を消して比較したいときに使う。
HDAエイチディーエー · Houdini Digital Asset
作ったネットワークを1つのノードとしてまとめ、部品として再利用できるようにしたもの。中身を隠して必要なパラメータだけ外に出せる。
.hip / .hipncヒップ / ヒップエヌシー
Houdiniのシーンファイル。.hip が通常版で、.hipnc は非商用（Apprentice）版が保存する形式。.hipnc は商用版で開けない。
hythonハイソン
Houdiniの機能を使えるPython。GUIを開かずにノードを組んだりレンダリングしたりできるため、自動化の中心になる。関連: HOM
HOMホム · Houdini Object Model
PythonからHoudiniを操作するためのAPI。`hou` という名前のモジュールとして提供される。関連: hython
Apprenticeアプレンティス
無料で使える非商用ライセンス。出力にウォーターマークが入り、解像度は1920x1080まで、保存は .hipnc のみという制限がある。学習用途としては十分。

実測で覆した情報

ネット上で見かけたが、自分で動かしたら違っていたもの。 このプロジェクトではHoudiniの挙動は実測を正とする方針にしている。

  • 「Apprentice では hython / hbatch が使えない」 誤り

    フォーラム由来の情報として複数箇所で見かけたが、実測では普通に動いた。 Houdini 21.0.700 の Apprentice ライセンスで、GUIがライセンスを保持している状態でも hython を同時起動できた。OpenGL ROP / Karma ROP での headless レンダリングも成功している。 この誤情報を前提にGUI遠隔操作（hrpyc）方式を作りかけて無駄になった。

  • Apprentice ライセンスの入れ直しは hkey ではできない

    License Administrator（hkey.exe）からログインすると 「Installing licenses through hkey is reserved for non-apprentice accounts」と弾かれる。 正解は Houdini 本体を起動し、出てくる「Unable to Acquire a License」ダイアログから進めること。

  • mountain SOP のパラメータ名は roughness / octaves ではない

    実際の名前は rough / oct / lac。 一般的な名前で書くとパラメータが見つからずエラーになる。 ノードのパラメータ名は [p.name() for p in node.parms()] で確認してから使う。
