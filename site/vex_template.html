VEX 解説

VEX は、Houdini の中で「点や面ひとつずつに同じ計算をさせる」ための短いプログラムです。 このページでは、何をするものか、どこに書くか、どう書くか、書くと結果がどうなるかを、 これまでの実験で測ったことを根拠にまとめました。 プログラムを書いたことがない人に向けて書いています。

01 — WhatVEX とは

Houdini の形は、たくさんの点（ポイント）と、点をつないだ面（プリミティブ）でできています。 VEX を使うと、「1 つの点に何をするか」だけを書けば、Houdini がそれを全部の点に配って、同時に計算してくれます。

なぜ使うのか

  • ノードに無い処理を作れる。「高さで色を変える」「近くの点を数える」「条件に合う面だけ消す」のような、ちょっとした決まりを自分で書ける。
  • 速い。100 万個の点に同じ計算をさせたところ、VEX（点ごと）は 1.3 ミリ秒で終わった。同じ計算を 1 つのループで順に回すと約 170 倍、Python で書くと約 260 倍かかった（実験173）。
  • シーンのあちこちで同じ書き方が使える。点・面・ボリューム（升目の値）・シミュレーション中の粒に、同じ言葉で書ける。

ひとことで言うと：VEX は「点ひとつ分の指示書」です。点の位置 @P、色 @Cd のような、点が持っている値（アトリビュート）を読んだり書き換えたりします。

02 — Whereどこに書くか

いちばんよく使うのは attribwrangle（Attribute Wrangle）というノードです。

  1. ネットワークで Tab キーを押し、「Attribute Wrangle」と打って置く。
  2. 上に形（例：grid）のノードをつなぐ。Wrangle の入口は 4 つあり、いちばん左（番号 0）が「書き換える形」。
  3. つまみの画面の VEXpression の欄にコードを書く。書いたらすぐ結果がビューポートに出る。
  4. Run Over（ランオーバー）で、何ごとに走らせるかを選ぶ。既定は Points（点ごと）。

Run Over で「何ごとに」走るかが変わる

同じ @marker = 1.0; というコードでも、Run Over を変えると、できる値の置き場所が変わりました（実験009）。

Run Over何回走るか書いた値の置き場所向いていること
Points（既定）点の数だけ点点を動かす・色を塗る・大きさを決める
Primitives面の数だけ面面ごとに色を変える・面を消す
Vertices頂点の数だけ頂点（面の角）UV など、面の角ごとに違う値
Detail (only once)全体で 1 回形全体に 1 つ点や線を新しく作る・全体の数を数える
Numbers指定した回数置き場所は無かった（実験009 では値が作られなかった）

ほかに VEX を書ける所

ノード何ごとに走るか使った例
volumewrangleボリュームの升目 1 つずつPyro の速度 vel を、煙の無い升だけ 0 にした（実験204）
popwrangleシミュレーション中の粒 1 つずつ（毎ステップ）花びらを少しずつ回した（実践「桜の花びらが舞い散る」）
attribvopWrangle と同じコードの代わりに箱をつないで書く（VOP）。中身は VEX になる

03 — Grammar書き方の基本

1. 1 行に 1 つの指示。最後に「;」

@P.y = @P.y + 0.5;   // 点を 0.5 だけ上へ
@P.y += 0.5;          // 同じ意味の短い書き方

// から行の終わりまではメモ（コメント）で、計算には使われません。

2. 「@」で点の値を読み書きする

頭に @ を付けた名前は、いま計算している点（や面）が持っている値です。よく使うものは次のとおりです。

書き方中身例
@P位置（x, y, z の 3 つ組）@P.y で高さだけ
@Cd色（赤, 緑, 青。0〜1）@Cd = {1, 0, 0}; で赤
@N法線（面が向いている方向）@P += @N * 0.1; で外へふくらませる
@pscale大きさCopy to Points で並べた物の大きさになる
@ptnumいまの点の番号（0 から）乱数の種に使う
@numpt点の数@ptnum / (@numpt - 1.0) で 0〜1
@primnumいまの面の番号Run Over が Primitives のとき
@Time / @Frameいまの時刻（秒）/ フレーム動かすとき

無い名前に書くと、その名前の値が新しく作られます（実験009）。

3. 値の種類（型）

種類中身変数を作る書き方@ で書くときの頭文字
float小数float h = 0.5;f@height
int整数int n = 3;i@count
vector3 つ組（位置・色・向き）vector c = {1, 0.5, 0};v@dir
string文字string s = "rock";s@name
配列同じ種類の値の並びint ids[] = nearpoints(0, @P, 0.2);i[]@ids

自分で作る値（@height など）は、頭文字で種類を決めておくと安全です。@P・@Cd・@N などの決まった名前は、付けなくても正しい種類で読まれます。

4. 関数を使う

よく使う計算は、関数として用意されています。このサイトで測ったものを挙げます。

関数すること測って分かったこと
noise(p)場所ごとになめらかに変わる値0.06〜0.92 ほどにしか届かない（実験135）
snoise(p)0 を中心に上下する値±1 を超えて ±2 近くまで出る（実験135）
curlnoise(p)渦を巻く流れ（向き）湧き出しがほぼ無く、流した粒が固まらない（実験171・172）
rand(n)番号から 0〜1 の乱数同じ番号なら毎回同じ値
fit(v, a, b, c, d)a〜b の値を c〜d に直す範囲の外は端で止まる。止めたくなければ efit（実験137）
lerp(a, b, t)a と b を t の割合で混ぜるefit と同じ直線で、範囲の外も伸びる（実験137）
smooth(a, b, x)a〜b の間をなめらかに 0→1形は 3x² − 2x³（実験137）
nearpoints(0, P, r)半径 r の中の点の番号を、近い順に自分も先頭に入る（実験136）。pcfind と同じ結果・同じ速さ（実験181）
xyzdist(1, P)別の形の面までの距離2 万点で数ミリ秒（実験191）
addpoint / addprim点・面（線）を作るRun Over を Detail にして使うことが多い（下のお手本 5）
removeprim面を消す下のお手本 4
blackbody(温度, 白の温度)温度から炎の色引数は 2 つ要る。1000K と 1500K は同じ色で頭打ち（実験026）

5. つまみを作って、数字をあとから動かす

コードの中に ch("height") と書き、VEXpression の欄の右上にあるボタン（＋の付いた四角）を押すと、「height」というつまみ（スライダー）が Wrangle に付きます。数字をコードに直接書く代わりにこれを使うと、コードを開かずに結果を調整できます。

@P.y += noise(@P * 2) * ch("height");

6. 2 つめの入力を読む

Wrangle の入口は 4 つあり、左から番号 0・1・2・3 です。関数の最初の数字でどの入力を読むかを選びます。たとえば xyzdist(1, @P) は「入口 1 につないだ形まで、いまの点からの距離」です（下のお手本 6）。

06 — Traps落とし穴

実験や実践で実際につまずいたところです。

Run Over が違うと、値の置き場所が変わる

色を点に塗ったつもりが面に付いていた、ということが起きる。Wrangle を置いたら、まず Run Over を確かめる（実験009）。

Detail で全部の点をループすると遅い

Detail は 1 回だけ走るので、同時に並べて計算できない。点ごとの計算は Points で書く。約 170 倍の差が出た（実験173）。

noise() は 0〜1 いっぱいには出ない

0.06〜0.92 ほど。0〜1 に使いたいなら fit(n, 0.1, 0.9, 0, 1) などで伸ばす（実験135）。

fit() は範囲の外で止まる

はみ出した分を残したいなら efit() を使う（実験137）。

smooth(大きい数, 小さい数, x) は効かない

逆向きのなだらかな変化が欲しいときは、1 - smooth(小さい数, 大きい数, x) と書く（実践を作っていて気づいた）。

配列の { } の中に計算は書けない

{0, h, 0} のように変数を入れると止まる。set(0, h, 0) を使うか、append() で 1 つずつ足す。

nearpoints() は自分も返す

「ほかの点」だけがほしいなら、最大数を 1 つ多くして先頭を捨てる（実験136）。

for-each の中の @primnum は 0

1 つずつ切り出して計算しているため。何番目かが要るならメタデータを読む。そもそも Wrangle 1 つで書けないか先に考える（実験010・174）。

Python から Run Over を変えるときの番号

class のつまみは 0 = Detail、1 = Primitives、2 = Points。

07 — ChooseVEX・VOP・Python の使い分け

書き方向いているとき速さ（100 万点に同じ計算。実験173）
VEX（Wrangle）点・面・升ごとの計算ほぼ全部。まずこれ1.3 ミリ秒
VOP（箱をつなぐ）コードを書かずに組みたいとき。中身は VEX になる（測っていない）
Pythonファイルを読む・ノードを作る・シーンを組むなど、形の外の仕事1 点ずつだと約 260 倍。値をまとめて読み書きすると、1 点ずつより約 6 倍速い
