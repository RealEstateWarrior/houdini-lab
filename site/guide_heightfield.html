地形を削って草を生やす

2026年9月14日 公開8ステップ難易度 基本

HeightField は高さを「数の並び（）」として持つ仕組みで、の地形では難しい「水で削る」がそのまま計算できる。削った跡は debris や sediment といったレイヤーとして残るので、そこに草を生やしたり色を塗り分けたりできる。数字はすべて実験034〜037で実測したもの。

の数
8個
かかる時間
10分ほど
地形の解像度
100×100
元になった実験
実験034〜037
hip を開くguide_hf.hipnc 実験034 の全文

手順

  1. 地形の土台を出す
  2. 起伏を足す
  3. 水で削る
  4. メッシュに直す
  5. 面の向きを作る
  6. 浸食のレイヤーを点に読む
  7. 草を散らす
  8. 草を複製する

  1. 地形の土台を出すheightfield

    高さを2次元のボリュームとして持つ入れ物を作る。sizex / sizey を 200、gridspacing を 2.0 にした。解像度は size ÷ gridspacing で決まるので、これで 100×100 になる。この段階では面も点も無く、height と mask という2枚のボリュームだけが出てくる。

    Houdini の画面

  2. 起伏を足すheightfield_noise

    と同じ考え方で、高さのボリュームにを足す。amp を 120、elementsize を 80 にした。amp の数字がそのまま高さになるわけではなく、実測では amp 30 で高さの幅が 8.74（約0.29倍）。ただし倍率としては正確で、amp を4通り変えても「幅 ÷ amp」は 0.291329 と小数点以下6桁まで同じだった。

    Houdini のパラメータ画面

  3. 水で削るheightfield_erode

    山を削って谷に積もらせる。iterations を 4 にした。ここが HeightField を使う一番の理由で、レイヤーが2枚から7枚に増える（debris / sediment / flow / flowdir.x / flowdir.y が追加）。削れた場所・積もった場所・水の流れた向きが、あとから使える形で残る。

    Houdini のパラメータ画面

  4. メッシュに直すconvertheightfield

    HeightField のままではレンダできないので、最後にこれを通す。マス目1つが点1つになるので、100×100 なら 10,000点 / 9,801面。解像度がそのまま点数になるので、化は必要になったところで行う。

    Houdini のパラメータ画面

  5. 面の向きを作るnormal

    あとで草を立てるために N を作る。 を通すと面が無くなるので、ばらまく前にやる。

    Houdini のパラメータ画面

  6. 浸食のレイヤーを点に読むattribwrangle

    volumesample で、点の位置における sediment（積もった量）を読む。ついでに下り坂の向きも作る。高さを2か所サンプリングして差を取るやり方にしているのは、normal が N をに書くため、点のラングルから @N を読んでも空になるから。

    Houdini のパラメータ画面

  7. 草を散らすscatter

    地形の上に900個の点を散らす。ここで読んだレイヤーの値を density に使えば、「削れた場所には生えない」「積もった場所だけ濃くする」といった配り方ができる。

    Houdini のパラメータ画面

  8. 草を複製するcopy to points

    細い円錐を1本作り、点の上に複製する。は Z 軸に伸ばしておく（rx に 90 度）。 はテンプレートの Z 軸を点の N に合わせるので、Y 軸のままだと900本すべてが横倒しになる。

    Houdini のパラメータ画面

つまずくところ

gridsamples では解像度が変わらない

名前は「Grid Samples」だが、これを 128 にしても 1024 にしても 100×100 のまま動かない。解像度を決めるのは size ÷ gridspacing。細かくしたいときは gridspacing を下げる。実験034で確かめた。

flowdir.x と flowdir.y は入れ替えて使う

浸食が残す「水の流れた向き」は flowdir.x と flowdir.y の2枚に分かれている。地形は水平なので、素直に set(fx, 0, fy) と書きたくなるが、これだと下り坂を向かない（実験036で測った平均は 96.5度＝でたらめ）。8通り総当たりで試したところ、入れ替えた set(fy, 0, fx) だけが平均 39.9度まで下がった。

normal SOP が書くのはバーテックスの N

点のラングルから @N を読んでも空のまま。実験036では、これに気づかず草の向きがでたらめになった。点の N が要るなら、attribpromote でバーテックスから点へ移すか、この手順のように高さから自分で計算する。

v@flow という名前は使えない

convertheightfield はレイヤーを点アトリビュートとして持ってくるので、float の flow がすでに点に乗っている。そこへ v@flow とベクトルで書こうとすると型がぶつかる。実験036でこれに掛かった。名前を変える。

浸食の時間は回数に比例しない

100×100 で1回 0.68秒、4回 2.35秒。回数を4倍にしても時間は 3.5倍で、準備の分が乗っている。ただし実用の解像度（gridspacing を下げる）ではそのまま重くなるので、形が決まるまでは粗い解像度で試す。

完成図

完成したところ。削られた尾根と谷の上に、900本の草が立っている。
